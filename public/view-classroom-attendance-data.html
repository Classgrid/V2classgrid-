Flag Reasons Explained
Pasted Code

Student pasted the attendance code instead of typing it. This suggests someone shared the code via text message.

⚠ Flagged
Not in Classroom (GPS)

Student's GPS location is farther than the allowed radius from the teacher's location. They may not be physically present.

⚠ Flagged
GPS Denied

Student did not share their GPS location. Location permission was denied or unavailable on their device.

⚠ Flagged
Wrong Device

Student used a different device than their previously registered one. Could indicate someone else is marking for them.

⚠ Flagged
Cross-Account Device Abuse

Two or more student accounts tried to mark attendance from the same phone. Clear proxy attempt — second student is completely blocked.

✕ Blocked
Secure (No Flags)

All 6 security checks passed. Student typed the code, was within GPS range, and used their own device.

✓ Clean
Security Layers
Encrypted Code

Attendance code is hashed with bcrypt. Even the database never stores it in plain text.

Session Token

Each session gets a unique UUID token. Prevents API replay attacks and unauthorized marking.

Time Window

Sessions expire after the duration you set (30s–10min). Server clock is used — students can't fake time.

One Mark Per Student

Database-level unique index prevents any student from marking twice in the same session.

Important: Flagged students are still marked as Present — they are NOT marked absent. The flag is a warning for faculty review. Only the faculty can manually change a student's status using the override feature.
